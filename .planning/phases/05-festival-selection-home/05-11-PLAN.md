<objective>
Close gap G-05-5b-r2 (major regression of G-05-5b): the app restores a stale
saved festival (frequency-2026) on every cold-start even after the visitor
entered a DIFFERENT, UNSAVED festival.

Root cause (fully diagnosed in .planning/debug/cold-start-restores-unsaved-festival.md):
the 05-09 fix implemented "restore only a SAVED festival" as "only PERSIST when
saved" (festivals.tsx:223). That makes the persisted `active-festival-slug` a
sticky "last SAVED festival ever entered" value — entering an unsaved festival
neither writes a new slug nor CLEARS the existing one, so a previously-entered
saved festival stays stuck in MMKV and _layout.tsx restores it unconditionally.

Fix: entering an unsaved festival must CLEAR the persisted slug, so the restore
target always reflects the LAST entered festival (restored only if it was saved).
Consolidate the persist/clear decision into one pure, tested helper so every
festival-home entry point shares one authority — no whack-a-mole.

Purpose: cold-start lands on Home unless the last-entered festival was saved.
Output: a testable persist/clear helper, both (tabs) entry points routed through
it, and a unit test reproducing the exact regression.
</objective>
