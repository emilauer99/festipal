# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope note (read first)

Like Phase 4, this phase has **real, pixel-precise Claude Design mockups** as its north-star:
`docs/concept/designs/festival/` (13 screens, imported 2026-08-05, `festipal-screens.jsx` +
`festipal-ds.js` + `festipal-tokens.css`). Unlike Phase 4, Phase 5 does **not** implement any
mockup screen 1:1 — per `05-CONTEXT.md` (D-01 through D-08) it builds a **trimmed slice** of three
mockup screens (`OverviewScreen`, `MyFestivalsScreen`, `DashboardScreen`) plus a **new** global tab
bar (`FloatingNav`) that the mockup shows but this phase only partially wires up. This section
resolves every "mockup shows X, we build Y" gap so the executor never has to guess.

**This phase extends `packages/ui/src/tokens.ts`, it does not replace it.** Phase 4 already ported
the full brand type/spacing/color system. Phase 5 needs a handful of tokens Phase 4 never touched
(a real `radii` ramp beyond `control`/`pill`, translucent fill/border roles, and the glass/shadow
values for the floating nav) — see **Color** and **Spacing Scale** below for the exact additions.
Do not invent a second/competing token set.

**Resolved decisions (no user confirmation needed — traced to `05-CONTEXT.md` D-01..D-08 and the
imported design source):**

1. **FestivalCard loses its photo backdrop this phase.** The mockup's `FestivalCard` is a
   `Photo`-backed component (image + scrim + overlaid text). `05-CONTEXT.md` Deferred explicitly
   excludes "cover images (Photo)" this phase (no festival images exist in the seed/schema). This
   phase's `FestivalCard` is therefore a **flat, non-photo variant**: a plain `Card` (`--r-card`,
   `--surface-card`, `--border-subtle`) with stacked text content. See **Component Contract**
   below for the exact layout — this is the single biggest visual deviation from the mockup file
   and the executor must build this variant, not copy `festipal-ds.js`'s `FestivalCard` verbatim.
2. **Status badge repurposed from ticket-status to saved-status.** The mockup's `Badge` on
   `FestivalCard` reads "Angemeldet" / "Empfohlen" / "Vorbei" (ticket/attendance status). Per D-05
   this becomes a binary **saved / not-saved** indicator: `Badge tone="brand"` reading "Gespeichert"
   when saved, nothing (a Save affordance instead) when not. Countdown capsule, ticket badge, and
   friends-count row are all dropped (D-05 — conflicts with gate-less `MyFestival`, ADR-014).
3. **`MyFestivalsScreen`'s `SegmentedControl` options change from Kommend/Vergangen to Meine/Alle**
   (D-05, FEST-02), default **Meine**. The search `Input`, the "2 Tickets in der Wallet" `Card`,
   and the "Ticket oder Code hinzufügen" button are all dropped (ticket/wallet framing out of
   scope, ADR-014).
4. **`OverviewScreen` (Home tab) is reduced to two elements** (D-04): the "dein nächstes Festival"
   hero `FestivalCard` + "Festival öffnen" button (Ticket button dropped — no ticket model), and
   the "Meine Festivals" `Rail`. The Artists rail, "Könnte dir gefallen" recommendations, global
   News, and "Festipal folgen" social row sections are entirely omitted (no backing data/features
   yet — D-04).
5. **`DashboardScreen` (festival home) is reduced to an identity block + a static "coming soon"
   menu** (D-07): name/dates/place key facts + 4 disabled tiles (Timetable/Lageplan/Cashless/News).
   Every other Dashboard section (Jetzt live, Stages, Als Nächstes, the live Cashless-balance card,
   News list, Featured rail, Social row) is dropped — see **Component Contract → Coming-soon
   tiles**, a new pattern invented for this phase (the mockup has no disabled-tile precedent).
6. **New global tab bar (`FloatingNav`), 4 items, 2 live + 2 disabled** (D-02): Home · Festivals ·
   Friends · Profil. The mockup's 5-item `GLOBAL_NAV` (Home/Festivals/**Artists**/Friends/**Mehr**)
   is trimmed — Artists is fully omitted (own later milestone) and "Mehr" (Einstellungen) is
   relabeled "Profil" per D-03. Friends and Profil render but are **visibly disabled** ("coming
   soon" — muted color, `accessibilityState={{ disabled: true }}`, no navigation on tap) until
   Phase 6. See **Component Contract → Tab bar** for the exact disabled treatment.
7. **No `TopBar` glass header, no profile avatar button, this phase.** The mockup's `TopBar`
   component (home icon + centered title + profile avatar) is not built. Screens keep the existing
   native Expo Router `Stack.Screen` header pattern already used by `festivals/index.tsx` (plain
   title, no glass/blur) — consistent with Phase 3/4's established pattern, avoids inventing a
   second header system for one phase. The mockup's top-right profile-avatar affordance is
   deliberately NOT added; the disabled Profil tab is the sole placeholder for that entry point
   this phase (D-03).
8. **Logout icon-button stays put.** Phase 4 placed it on the Festivals screen header ("moves to
   Profil/Settings as the shell grows" — 04-CONTEXT). It does **not** move this phase (the Profil
   tab is a disabled placeholder, not a real screen, until Phase 6) — no change to its position or
   styling.
9. **New dependency this phase:** `expo-blur` (official Expo package, provides `BlurView`) — needed
   for the floating nav's backdrop blur (`--glass-blur: 22px`, `--glass-saturate: 180%`). Not
   currently installed (verified against `apps/mobile/package.json`). `lucide-react-native`,
   `react-native-svg`, `expo-image`, fonts — already installed (Phase 4), no new icon/font deps.
10. **Dark-first, light fully supported, no manual toggle** — unchanged carry-over from Phase 4
    (`useColorScheme()`-driven, `packages/ui/src/tokens.ts` `colors`/`lightColors`).
11. **Unsave is out of scope.** Neither `REQUIREMENTS.md` (FEST-03) nor `05-CONTEXT.md` mentions
    removing a saved festival. The "Gespeichert" badge this phase is a **status indicator only**,
    not a toggle — tapping a saved card's badge does nothing (only unsaved cards render a tappable
    Save affordance). Do not build an unsave action.
12. **Violet (`--brand-secondary`) is not used anywhere in this phase's three screens.** Reserved
    for later phases (Artists, Crew, Timetable "Friends" mode) per the design's own usage pattern
    (`Card tone="secondary"` only appears on Artists/Settings screens, both out of scope). Do not
    introduce it here "for variety."

## Component Contract

Concrete shape for the two components this phase invents/deviates on (not literal transcriptions
from `festipal-ds.js` — see Scope notes #1 and #5).

### FestivalCard (flat, non-photo variant)

A `Card` (`surfaceCard` background, `borderSubtle` 1px border, `radiiScale['r-card']` = 22px
radius, `spacingScale['sp-6']` = 16px padding), containing, top to bottom:

1. **Header row** (flex-row, space-between): festival name (`title3`, `textPrimary`, single line,
   `numberOfLines={1}` + ellipsis — long-text backstop, see UI Considerations) on the left; on the
   right, either the "Gespeichert" `Badge` (`fillBrandQuiet` bg, `colors.primary` icon `check` +
   text, `micro`) if saved, or a quiet Save `Pressable` (`fillQuiet` bg, `radiiScale['r-pill']`,
   `hitMin` height, icon `plus` + "Speichern"/"Save" text, `micro`) if not.
2. **Caption row** (`spacingScale['sp-4']` gap above): `"{dates} · {place}"` in `bodySm`,
   `textMuted` — dates formatted via `Intl.DateTimeFormat` (D-08), single line.

The whole card is `Pressable` (enters the festival, gate-less, always enabled) EXCEPT the Save
affordance, which calls `e.stopPropagation()`-equivalent (`onPress` on the inner `Pressable` must
not bubble to the card's `onPress`) — same pattern as the mockup's Cashless-tile "Bezahlen" button
inside `DashboardScreen`'s `Card interactive`.

**Home hero variant:** same structure, larger — `title2` (21px) name instead of `title3`, and a
full-width primary `Button` ("Festival öffnen", icon `arrow-right`) rendered below the card instead
of inline in the header row (the hero's save-affordance/badge still renders in the header row).

### Coming-soon tile (new pattern, no mockup precedent)

A 2×2 grid (`gap: spacingScale['sp-5']` = 12px) of 4 tiles: Timetable (`calendar-clock`), Lageplan
(`map-pin`), Cashless (`wallet`), News (`newspaper`). Each tile is a `View` (not `Pressable` —
non-interactive, `accessibilityState={{ disabled: true }}` if made focusable at all):
`surfaceCard` background, `borderSubtle` border, `radiiScale['r-md']` = 16px radius, centered icon
(`textMuted` color, 22px) + label (`title3`, `textMuted`) + a small "Bald"/"Soon" `Badge`
(`micro`, `fillQuiet` bg, `textMuted` fg — deliberately NOT `fillBrandQuiet`/accent, since this is
an inert state, not a call-to-action) in the tile's top-right corner. No press feedback, no
navigation. This tile shape becomes the real Timetable/Lageplan/Cashless/News entry points in
later content phases — do not build it as a throwaway static image.

### Tab bar (`FloatingNav`)

4 items — Home (`home`), Festivals (`tent`), Friends (`users`, disabled), Profil (`user-round`,
disabled) — floating pill, `position: absolute`, `left/right: layout.screenPad`,
`bottom: layout.navInset + safe-area-bottom`, `height: layout.navHeight`, `borderRadius:
radiiScale['r-pill']`, `glassFill` background composited via `expo-blur`'s `BlurView`
(`intensity` tuned to approximate `--glass-blur: 22px` / `--glass-saturate: 180%`), `glassBorder`
1px border. Active item: icon `strokeWidth={2.4}` in `colors.primary`, label in `colors.primary`,
a `fillBrandQuiet` tint-pill rendered behind icon+label. Inactive-but-enabled item (Home/Festivals
when not active): icon `strokeWidth={2}`, `colors.textMuted`. **Disabled item (Friends/Profil):**
same icon/label as an inactive item but at reduced opacity (`0.4`, matching the existing disabled-
`Button` convention already in `festipal-ds.js`), `onPress` is a no-op, `accessibilityState={{
disabled: true }}`, and the `accessibilityLabel` appends "— coming soon" / "— bald verfügbar" so
screen readers announce intent rather than a silently broken button. No extra badge/dot on the tab
item itself (kept visually clean — space-constrained, unlike the coming-soon tiles which have room).

## Visual Hierarchy — Focal Points

One declared primary visual anchor per surface (the element the eye should land on first;
everything else is secondary/supporting). Uses the copy and tokens already declared above.

- **Home tab** — Focal point: the **hero `FestivalCard` + "Festival öffnen" CTA** (accent green
  fill + glow, full-width, pill radius, ≥44px `hitMin` target). The "Meine Festivals" rail below is
  explicitly secondary (smaller cards, no CTA of its own — tap-to-enter only).
- **Festivals tab** — Focal point: the **`SegmentedControl`** (Meine/Alle) as the primary
  navigational anchor at the top, with the resulting **FestivalCard list** as the content focal
  point beneath it. Each card's own focal point is the name + saved-badge/save-affordance pairing
  in its header row.
- **Festival home** — Focal point: the **festival name** (`display2`, 34px, the screen's H1),
  anchored at the top. The dates/place key-fact rows are secondary supporting detail. The
  coming-soon tile grid is explicitly de-emphasized (muted colors throughout, doc 03's "dezent"
  framing from D-07) — it must never visually compete with the identity block above it.
- **Tab bar** — Focal point: whichever of Home/Festivals is currently active (accent tint-pill +
  accent icon/label). Friends/Profil are deliberately the lowest-emphasis elements on screen
  (0.4 opacity) — visible but never competing for attention.
