<objective>
Close three UAT navigation gaps in the Festivals/Home tab shell:

- G-05-2 (major): the see-all / "Alle Festivals ansehen" CTA fails to re-open the Alle segment when the Festivals tab is already mounted with a manually-switched segment.
- G-05-5b (major): cold-start restores an entered-but-UNSAVED festival; it must only restore SAVED festivals.
- G-05-5a (minor): Back from a cold-start-launched festival home lands on the Festivals tab; it should land on the Start/Home tab.

Purpose: Make the cross-tab segment CTA reliable and make cold-start restore semantically correct ("restore the festival you opened, only if it is saved"), per the user's fixed product intent in 05-UAT.md.
Output: A new consume-once segment-request singleton (+ unit test), an enter-gate that persists the active slug only for saved festivals, and a corrected cold-start Back fallback.
</objective>

  <name>Task 1 (G-05-2): consume-once segment-request singleton + focus-effect re-sync</name>
  <files>apps/mobile/lib/festivals-segment-request.ts, apps/mobile/lib/__tests__/festivals-segment-request.test.ts, apps/mobile/app/(tabs)/home.tsx, apps/mobile/app/(tabs)/festivals.tsx</files>
  <behavior>
    festivals-segment-request singleton:
    - requestFestivalsSegment('alle') then consumeFestivalsSegment() returns 'alle'.
    - a second consumeFestivalsSegment() with no intervening request returns null (consume-once, drains the pending value).
    - consumeFestivalsSegment() with no prior request returns null.
    - a later requestFestivalsSegment('meine') then consume returns 'meine' (last-write-wins).
  </behavior>
  <action>
    Root cause (05-UAT.md G-05-2): festivals.tsx re-syncs the segment via useEffect keyed on the derived param value; the Home CTA always targets the same segment=all param, so on a second navigation the value is unchanged, the effect never re-fires, and the manually-set 'meine' state survives because the tab stays mounted across bottom-tab switches.

    Fix uses the codebase's existing module-level consume-once idiom (mirror pending-destination.ts exactly — plain in-memory module var, NOT MMKV/SecureStore; a stale cross-session segment request is not wanted):

    1. Create apps/mobile/lib/festivals-segment-request.ts. Export a Segment union type ('meine' | 'alle'), a requestFestivalsSegment(segment: Segment): void setter, and a consumeFestivalsSegment(): Segment | null reader that returns the pending value and clears it to null. Document that this is the cross-tab "open Festivals on this segment" intent, consumed once by the Festivals tab's focus effect so a plain bottom-tab focus (no queued request) never clobbers a manual SegmentedControl tap (05-UAT.md G-05-2 "without clobbering manual taps on plain tab-bar focus").

    2. In home.tsx goToAllFestivals: before navigating, call requestFestivalsSegment('alle'), then keep router.push('/festivals?segment=all') (the static literal still typechecks under typedRoutes and seeds the initial segment when the tab is mounting fresh; the queued request covers the already-mounted case). Import requestFestivalsSegment from ../../lib/festivals-segment-request. Note in a comment that both the empty-state "Browse festivals" CTA and the rail "Alle" see-all go through this one function, so both are covered.

    3. In festivals.tsx: keep the useState(() => normalizedParam) initializer (initial mount from the param is still correct). REMOVE the existing useEffect(() => setSegment(normalizedParam), [normalizedParam]) re-sync (lines ~74-76) — it is the exact mechanism that cannot re-fire on an unchanged param. Replace it with a useFocusEffect (imported from expo-router) whose callback is wrapped in useCallback([]): on every focus, read consumeFestivalsSegment() and, only if it returns a non-null segment, setSegment(that). Plain tab-bar focus queues no request -> consume returns null -> manual segment is preserved. Import { useFocusEffect } from 'expo-router' and useCallback from 'react'.

    Do NOT introduce a nonce URL param (avoids typedRoutes Href friction) — the singleton is the driver. Keep the segment=all param only as the initial-mount seed.
  </action>
