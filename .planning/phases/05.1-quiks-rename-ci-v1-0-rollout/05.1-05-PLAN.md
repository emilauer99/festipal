    Apply the standard migration to all four screens, plus the status-colour correction.

    Shared migration shape (identical to plan 04, PATTERNS.md § Shared Patterns is canonical):
    - Non-colour scales (`typeRoles`, `layout`, `radiiScale`, `spacingScale`) may stay destructured
      at module scope; every `colors.*` reference moves into a module-private
      `createStyles(colors: ThemeColors)` returning `StyleSheet.create({...})`.
    - In the component body: `const { colors } = useTheme();` then
      `const styles = useMemo(() => createStyles(colors), [colors]);`.
    - Colours passed as props (Lucide icon `color=`, `ActivityIndicator` colour, `RefreshControl`
      tint, and similar) resolve from the same `colors`, not from a module-scope destructure.
    - Remove the numeric `fontWeight` from any style whose `fontFamily` comes from
      `fontFamilyForRole` (plan 03's documented rule).

    `danger` token as a TEXT colour — the transport/response error block, the retry-affordance

    `dangerText` instead. The bare `danger` token stays only where it fills a surface. Copy is
    unchanged; this is a colour swap.

    Explicitly do NOT change in these files: any user-facing string, any route or navigation call,
    the empty/loading/error BRANCHING logic, the hero-vs-rail selection, or any query/mutation
    behaviour. The hero is replaced (not recoloured) for the empty and error states today and that
    stays true — the gradient has no empty or error variant.
