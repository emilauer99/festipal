## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 4.1.10 (both `apps/mobile` and `apps/api`) |
| **Config file** | `apps/mobile/vitest.config.ts` (node env, `lib/` scope) · `apps/api/vitest.config.ts` + `apps/api/test/setup.ts` (needs running Postgres) |
| **Quick run command** | `pnpm --filter ./apps/mobile test` (11 files, 94 tests, ~0.5 s — no device/DB) |
| **Full suite command** | `pnpm test` (root, Turbo across all packages; `apps/api` needs the `docker compose` stack up) |
| **Estimated runtime** | ~0.5 s quick · full suite dominated by `apps/api` DB spin-up |

> **Filter form.** All plans address workspaces by PATH (`--filter ./apps/mobile`,
> `--filter ./apps/api`, `--filter ./packages/ui`) rather than by package name. This is deliberate:
> the scope rename (ADR-024, plan 05.1-01 Task 2) changes every package `name` field mid-phase, so a
> name-based filter would break in the middle of the wave. Path filters survive the rename.

---

## Sampling Rate

- **After every task commit:** `pnpm --filter ./apps/mobile test` + `pnpm --filter ./apps/mobile lint`
- **After every plan wave:** `pnpm lint && pnpm typecheck && pnpm test` (root)
- **Before `/gsd-verify-work`:** Full suite green **plus** mandatory on-device acceptance (Android, both color modes, login/logout, deep link, cold start) — node-env vitest alone is not sufficient evidence for RN routing/native behavior
- **Max feedback latency:** ~30 seconds (quick run) / minutes (root suite)
