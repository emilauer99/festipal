# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope note (read first)

This phase is explicitly **unstyled by decision** (CONTEXT.md D-01/D-04, Claude's Discretion:
"keep unstyled and minimal"). `apps/mobile` does not exist yet at time of writing — this is a
greenfield Expo Router app, not a React/Next.js/Vite web app, so the `shadcn` gate does not
apply (RN has no shadcn/web component registry). Real, designed screens land in Phases 4–6
under Claude Design fidelity (CLAUDE.md Architecture Principle 5). This contract exists so that:

1. Placeholder screens are visually **consistent enough** not to look broken (reuse
   `packages/ui/src/tokens.ts`, the project's existing placeholder token set — do not invent a
   second, competing token set for this phase).
2. Every **user-facing string** this phase actually ships (OTP flow, festival list, splash) has
   locked copy, since I18N-01 requires real DE/EN catalogs from the first commit — copy is the
   one design dimension that is NOT deferred, unlike visual styling.
3. Phases 4–6 executors can tell at a glance which strings are placeholder-but-real (must be
   preserved/extended) vs. which visuals are throwaway (safe to fully restyle).

## Spacing Scale

Declared values (must be multiples of 4) — from `packages/ui/src/tokens.ts` `spacing`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/text inline gaps (e.g. label-to-input gap) |
| sm | 8px | Compact element spacing (OTP digit gaps, list-row internal padding) |
| md | 16px | Default element spacing (screen horizontal padding, form field gaps) |
| lg | 24px | Section padding (between form and CTA button, list-row vertical padding) |
| xl | 32px | Layout gaps (splash wordmark to below-fold content, if any) |
| 2xl | 48px | Major section breaks (rare this phase — placeholders are single-section screens) |

Exceptions:
- **44px minimum touch target** for the single-column CTA buttons (Send code / Verify / Save /
  Enter) and any pressable list row — accessibility floor, applies even to unstyled placeholders.
- `3xl` (64px) is **not defined** in `packages/ui/src/tokens.ts` and is **not needed** this
  phase (no page-level spacing at that scale on single-section placeholder screens); do not add
  it speculatively — a later phase can add it when a real screen needs it.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | regular (400) | 1.5 |
| Label | 14px | semibold (600) | 1.4 |
| Heading | 20px | semibold (600) | 1.2 |
| Display | 32px | semibold (600) | 1.2 |

All four sizes (16/14/20/32) map exactly to existing `packages/ui/src/tokens.ts` `fontSizes`
(`md`/`sm`/`lg`/`2xl`) — no new size tokens needed. Only **two weights** are used this phase:
regular (400) for body copy, semibold (600) for everything emphasized (labels, buttons, headings,
the splash wordmark) — do not reach for `medium`/`bold` from the tokens file this phase, even
though they exist there for later use.

**Usage this phase:**
- **Body** — form helper text, error/empty-state copy, list-row secondary text (dates, place).
- **Label** — button text, input labels, festival name in list rows.
- **Heading** — screen-level titles if a screen has one (e.g. "Festivals" list header).
- **Display** — splash-screen "festipal" wordmark only (D-04 placeholder branding).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`colors.background`) | Screen backgrounds |
| Secondary (30%) | `#f4f4f5` (`colors.muted`) | List-row backgrounds, input field backgrounds, splash background |
| Accent (10%) | `#4f46e5` (`colors.primary`) | Primary CTA buttons only, focused-input border, active-state indicator |
| Destructive | `#dc2626` (`colors.danger`) | Error-state text/border only (wrong/expired OTP code, rate-limit message, network-error message) |

Accent (`#4f46e5`) reserved for **exactly these elements, nothing else**:
- "Send code" button (email entry screen)
- "Verify" button (OTP entry screen)
- "Save" button (festival list row)
- "Enter festival" button (festival list row / detail)
- Focused `TextInput` border (email field, OTP digit fields)

All static/secondary text uses `colors.foreground` (`#0a0a0a`) or `colors.mutedForeground`
(`#71717a`) for de-emphasized copy (helper text, dates/place in list rows) — both already exist
in `packages/ui/src/tokens.ts`; no new colors needed.

**No destructive actions exist in this phase's scope** (logout is AUTH-04, Phase 4; no
delete/remove actions this phase). The `danger` color is used only for **error state**, not a
confirmation flow.

## Copywriting Contract

Source language is **English** (D-08) — every string below is the Lingui `t()`/`<Trans>`
macro's source text; the German catalog (`locales/de/messages.po`) is the translation and must
match the binding German concept terms exactly where they exist (e.g. "Meine Festivals" —
`docs/concept/`). Per D-07, devices whose language is neither `de` nor `en` see the **German**
strings, not English — this is a deliberate fallback-locale choice for this phase, orthogonal to
DEFAULT_LOCALE's currently-unresolved code-level wiring (see RESEARCH.md Open Question 3 —
planner-level, not a copy decision).

| Festival list CTA (unsaved) | "Save" |

| Screen title — Festivals list | "Festivals" |
| Screen title — email entry | "Log in" |
| Screen title — OTP verify | "Enter your code" |

| error | email-entry, otp-verify | ✅ covered | See Copywriting Contract error rows (wrong code, expired code, rate-limited) |

| populated | festivals-list | ✅ covered | Normal state shows one real seeded row ("Frequency 2026") with name, dates, place, and a Save/Enter CTA per the row's saved-state |
| partial | email-entry | ✅ covered | Single-field form — no partial-data state exists; "Send code" stays disabled/inert until the email field is non-empty |
| partial | otp-verify | ✅ covered | A partially-entered code simply leaves "Verify" disabled/inert until 6 digits are present — no partial-submit state to design |
| partial | festivals-list | ✅ covered | Rows with a missing optional field (dates/place) omit that line rather than render a blank; festival name is always present (non-optional in the `packages/contracts` schema), so a row can never render nameless |

| overflow | otp-verify | ✅ covered | Six fixed-width single-digit boxes with `maxLength` per box — content length is fixed by construction, overflow impossible |
| overflow | festivals-list, festival-home | ✅ covered | List scrolls vertically; festival name/place `Text` wraps by default in RN (no truncation/ellipsis needed for unstyled placeholders); do not set `numberOfLines` this phase |
| long-text | email-entry | ✅ covered | RN `TextInput` scrolls long email addresses by default; no character limit imposed client-side (server validates via existing Zod schema) |
| long-text | otp-verify | ✅ covered | Input constrained to exactly 6 digits (`maxLength` + numeric keyboard) — a long-text state cannot occur |
| long-text | festivals-list, festival-home | ✅ covered | Festival name/place wrap onto multiple lines by default (no `numberOfLines`); layout is single-column so wrapping cannot collide with siblings |

| empty, loading, error, partial, overflow, long-text | profile-stub | 🧪 backstop | Whether this screen is built at all is Claude's Discretion at plan time (RESEARCH.md Open Question 1); IF built, use Copywriting-Contract-equivalent minimal copy: heading "One more step", body "We need a temporary profile to continue.", CTA "Continue" (auto-fills placeholder username/displayName, calls existing `POST /me/complete-profile`), submit states mirroring email-entry (disabled-while-submitting, error copy with retry path). Verification: confirm at plan/execute time whether this screen exists in the shipped route tree — if it does, its copy and states must match this row; if it doesn't (pre-provisioned test account chosen instead), this row is N/A. |
