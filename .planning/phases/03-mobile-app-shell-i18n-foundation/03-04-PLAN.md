<objective>
Build the real (unstyled) email-OTP login screens and the minimal profile-setup stub that lets a
genuinely first-time account get all the way in.

Purpose: D-02 requires a rudimentary but REAL OTP flow (email → 6-digit code → in) — no dev bypass —
that survives a kill-and-relaunch and that Phase 4 will style and extend as the SAME flow. Because a
brand-new OTP account's `GET /me` returns `profile: null` (Phase 2), the four-state guard's
`authenticated-no-profile` branch needs somewhere to route; a minimal stub calling the already-built
`POST /me/complete-profile` (RESEARCH recommendation (a)) keeps the flow demonstrable end-to-end and
the guard genuinely exercised, without pretending to be Phase 4's designed profile UI.

Output: `(auth)` email + verify screens, and the `(profile-setup)` stub — all Lingui-wrapped.
</objective>

| T-03-10 | Denial of Service | OTP resend/rate-limit | low | mitigate | Server already rate-limits (Phase 2); the client surfaces the localized "try again in a few minutes" state instead of silently retrying. |
