<objective>
Stand up the local dev infrastructure and the backend wiring that lets a real device
authenticate against the local API and read its OTP codes, so every later mobile plan can
be exercised end-to-end on a phone over LAN Wi-Fi.

Purpose: The mobile app (plans 02–05) is almost entirely faithful wiring to already-built
Phase 1/2 server logic. Before that wiring can be device-tested, three things must exist that
do not today: (1) a local Postgres+Mailpit stack (D-11) so the API runs fully offline of Neon
and OTP codes are readable in a web inbox, (2) `trustedOrigins` on the better-auth instance so
the Expo client's `festipal://`/`exp://` requests are accepted (D-05), and (3) a Mailpit SMTP
transport so `OTP_EMAIL_TRANSPORT=mailpit` routes codes to the readable inbox.

Output: `docker-compose.yml`, a `mailpit` OTP transport, `trustedOrigins`, and env plumbing.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Expo client → better-auth (`/api/auth/*`) | The app scheme (`festipal://`/`exp://`) is the Origin better-auth's CSRF/origin check validates. |
| Dev device → local API over LAN (cleartext HTTP) | OTP request/verify traffic crosses shared Wi-Fi in dev only. |
| Mailpit web UI (:8025) | OTP codes are readable by anyone on the LAN during dev testing. |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | `trustedOrigins` | high | mitigate | Whitelist exact `festipal://` + `exp://` dev-client schemes only; no bare `*` wildcard on the production scheme. |
| T-03-02 | Information Disclosure | Mailpit inbox / cleartext LAN | low | accept | Dev-only infrastructure; documented accepted risk (D-10). Production uses Resend over HTTPS, unchanged. |
| T-03-03 | Information Disclosure | `.env.example` | high | mitigate | Placeholder secrets only; `BETTER_AUTH_SECRET` stays server-side, never in any `EXPO_PUBLIC_*` var. |
| T-03-SC | Tampering | npm install (`nodemailer`) | medium | mitigate | `nodemailer` is an established, high-traffic package (not in RESEARCH's `[ASSUMED]`/`[SUS]` legitimacy list); pin a current version and confirm `npm view nodemailer version` at install. |
</threat_model>
