<objective>
Scaffold the greenfield `apps/mobile` Expo Router app and prove the build/monorepo/i18n spine
end-to-end with one production-quality vertical slice: the app boots, Metro resolves the
`@festipal/*` workspace packages, and the first screen renders a device-locale-resolved Lingui
string — with the `no-literal-string` lint rule already enforcing i18n before any product screen
ships.

Purpose: This is the tracer for the whole phase. The two highest-risk architectural facts to
prove early — before pouring auth/API/screen work on top — are (1) Metro's pnpm workspace
resolution (Pitfall E: `@festipal/*` imports otherwise silently fail or resolve stale) and (2)
that the very first UI string is localized and lint-enforced (Pitfall 7: literal strings creep in
if the rule lands after screens). Proving both on the app's best early-context tokens catches an
architectural dead-end after one commit instead of after five layers.

Output: a bundling Expo app skeleton, real DE/EN Lingui catalogs, the `no-literal-string` rule,
and the D-07 German UI-fallback wired into `resolveUiLocale`.
</objective>

### Decision (D-07, RESEARCH Open Question 3) — surfaced per CONTEXT Claude's-Discretion
We add an optional `uiFallback?: Locale` parameter to `resolveUiLocale` (default = `DEFAULT_LOCALE`)
rather than changing the shared `DEFAULT_LOCALE` constant. Rationale: `DEFAULT_LOCALE` is re-exported
through `@festipal/contracts` and doubles as the content-axis neutral default (ADR-012); flipping it
globally would couple the UI-axis fallback to the content-axis default. The mobile app passes
`uiFallback: 'de'`; the shared constant stays `'en'`. This keeps the content axis untouched and makes
an in-app switcher additive later.
