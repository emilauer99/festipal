<assumption_delta_decision>
## Identity-model primary noun (advisory, recorded per assumption-delta checkpoint)

- **Primary noun:** the global `user` / **Account** (better-auth's own table) is the identity
  root. `VisitorProfile` is a per-account *detail* table (1:1, keyed by `accountId`), and
  `my_festival` is a gate-less *save-membership edge* — NOT better-auth's `organization` plugin,
  NOT its `username` plugin.
- **Decision:** `no-change` — this is greenfield; the model is being *established*, not
  generalized from a prior singular/required/derived shape. There is no promote/add-alongside
  transition to reconcile.
- **Rationale / citations:** ADR-014 (tenant boundary: global Account carries no `festivalId`;
  join = save), ADR-016 (Account -> Visitor/Staff/Admin split), CONTEXT.md D-01/D-04. This block
  is the in-plan record; the durable ADR note is written by Task 3.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> repo | Third-party packages (better-auth, auth CLI, drizzle-zod) enter the build; a hijacked/typosquatted publish crosses here |
| CLI codegen -> vendored schema/auth.ts | Generated code is trusted as the authoritative auth-table shape and consumed by every downstream layer |
| global identity (user/Account) -> tenant data (festival) | The schema-level boundary that must stay unbridged except via my_festival |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | npm installs (better-auth, auth, drizzle-zod) | high | mitigate | Task 2 blocking-human legitimacy checkpoint verifies packages on npmjs.com before install; exact versions pinned in package.json |
| T-01-AV | Tampering | Vendored schema/auth.ts trusted as auth truth | medium | mitigate | Provenance header marks it GENERATED / do-not-hand-edit with a regenerate command; better-auth version pinned so regen is reproducible |
| T-01-UN | Spoofing | username/displayUsername leaking onto shared user table via a plugin | high | mitigate | organization/username plugins deliberately NOT declared in auth.config.ts; acceptance asserts those columns are absent from the generated user table |
| T-01-XT | Information Disclosure | Global Account gaining a festival scope | high | mitigate | user table carries no festival-scoping column (asserted by reading auth.ts); recorded as a prohibition |
</threat_model>
