# External Integrations

**Analysis Date:** 2026-07-29

## APIs & External Services

**Note:** This is a greenfield project being scaffolded. Core integrations are *planned* per ADRs but not yet fully implemented. Only the database connection is active.

### Cashless Integration (Planned - ADR-011)

- **Service:** Per-festival embedded cashless URL (no festipal payment processing)
  - What it's used for: Festival-specific payment/wallet system integration
  - No SDK; URL is stored in Festival tenant record (`festival.cashlessUrl`)
  - **App implementation:** `react-native-webview` (WebView in React Native)
    - Only HTTPS URLs allowed
    - Sandboxed to configured domain only
    - Parameters: optional deep-link to user's account page
  - **Admin implementation:** iframe preview when configuring URL
  - **Security:** festipal never processes, stores, or handles card/payment data (PCI-DSS exempt)
  - **Config:** Each Festival stores its cashless URL; if absent, section is hidden
- **Auth:** None (third-party provider handles auth internally)
- **Data flow:** App opens WebView → Cashless provider → user completes transaction → back to app

### Maps (Planned - ADR-008)

- **Service:** MapLibre
  - What it's used for: Festival site map (Lageplan), venue/stage locations, vendor positions
  - **SDK:** `@maplibre/maplibre-react-native` (React Native)
  - Custom festival maps: custom tilesets per festival (self-hosted or third-party tile server)
  - **Data storage:** Festival map tiles/config stored in DB (TBD schema)
- **Auth:** None required (static maps)
- **Cost:** Self-hosted tiles or open-source tile server (no per-view fees like Google Maps)

### Realtime (Planned - ADR-010)

- **Service:** NestJS WebSocket Gateway + Redis adapter
  - What it's used for: Live updates (friends presence, activities, chat, push notifications)
  - **SDK:** Not external; built in NestJS with `@nestjs/websockets` and Redis adapter
  - **Redis:** External Redis instance (hosted on Railway per ADR-010)
- **Auth:** better-auth session tokens
- **Data flow:** Client establishes WebSocket → NestJS gateway → Redis pub/sub → multi-server broadcast

## Data Storage

**Databases:**

- **PostgreSQL 18** (Neon, serverless)
  - **Connection URLs:**
    - **Pooled URL:** `DATABASE_URL` (for app runtime, drizzle-orm via postgres.js)
      - Used by: NestJS `apps/api` at `apps/api/src/config/env.ts` (required)
      - Setup: postgres.js with `prepare: false` for Neon pgBouncer pooling
    - **Unpooled URL:** `DATABASE_URL_UNPOOLED` (for Drizzle migrations only)
      - Used by: `packages/db/drizzle.config.ts` during schema generation/migration
  - **ORM:** Drizzle ORM 0.45.2
    - Config: `packages/db/drizzle.config.ts`
    - Schema: `packages/db/src/schema/` (festival, tag, locale tables)
    - Multi-tenant: all tables festival-scoped via `festival.id` foreign key
  - **Migrations:** SQL in `packages/db/drizzle/` directory (auto-generated by drizzle-kit)
  - **Region:** `eu-central-1` (Frankfurt) — co-located with Railway backend, DSGVO compliant
  - **Features:**
    - Branching (for preview/CI environments)
    - Connection pooling (pgBouncer at Neon proxy)
    - Autoscaling to zero (serverless)
  - **Schema Tables (current MVP):**
    - `festival` — Tenant root; `id` (UUID), `slug` (unique, text), `name`, `defaultLocale`, `cashlessUrl`, timestamps
    - `festival_locale` — Supported locales per festival (PK: festivalId + locale)
    - `tag` — Content category/tags (festival-scoped); `id`, `festivalId`, `slug`, timestamps
    - `tag_translation` — i18n translations (PK: tagId + locale); `title` per locale
    - `locale` — Enum table (future; currently defined in code)
  - **Future tables (ADR-014, not yet scaffolded):**
    - `user` (global, no festival_id)
    - `user_profile` (global)
    - `festival_user` (user's role in festival — guest, vendor, crew)
    - `timetable`, `act`, `stage` (festival-scoped)
    - `venue`, `vendor` (festival-scoped)
    - `swap_listing` (tauschbörse, festival-scoped)
    - `activity`, `activity_participant` (social, festival-scoped)
    - `friendship` (user-global, persists across festivals)
    - `presence`, `location` (festival-scoped, time-limited, friends only)

## Authentication & Identity

**Auth Provider (Planned - ADR-009):**

- **better-auth** (self-hosted, TypeScript)
  - What it's used for: User account creation, login, social logins, passkeys, multi-tenant session management
  - **SDK:** `better-auth` (NPM package, self-hosted — no external SaaS)
  - **Integration:** NestJS guard/middleware (TBD, not yet scaffolded)
  - **Databases:** Stores users + sessions in same PostgreSQL (Neon) as app data
  - **Multi-tenancy:** Organizations model = Festivals; user can join multiple festivals
  - **Session:** Active festival context stored in session/JWT (ADR-014)
  - **Social login:** TBD (GitHub, Google, etc. OAuth provider configs)
  - **Passkeys:** FIDO2/WebAuthn support
  - **Security:** Self-hosted auth means we own session/credential security; must review flows carefully
  - **Config:** `BETTER_AUTH_SECRET` (env var for session signing), `BETTER_AUTH_URL` (public auth endpoint)

**Current Status:**
- Schema/infrastructure ready (dependencies installed: `zod` for validation)
- Implementation started: `apps/api/src/config/env.ts` includes `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` placeholders
- Not yet wired: No auth guards, no session middleware, no user/organization schema

## Environment Configuration

**Required Environment Variables:**

Root `.env` file (git-ignored, not in repo):

```
# Backend Server
PORT=8081                      # (default, optional)

# Database
DATABASE_URL=postgresql://...  # Neon pooled connection string (REQUIRED)
DATABASE_URL_UNPOOLED=postgresql://...  # Neon direct URL for migrations (optional, defaults to DATABASE_URL)

# Authentication (for better-auth, optional until wired)
BETTER_AUTH_SECRET=...         # 32+ char random string for session signing
BETTER_AUTH_URL=http://localhost:8081/api/v1/auth  # Public-facing auth endpoint

# Realtime (for Redis adapter, optional until implemented)
REDIS_URL=redis://...          # Railway Redis or local Redis URL
```

**Secrets Location:**

- **Development:** `.env` file (local, never committed)
- **Production:** Railway environment variables dashboard or GitHub Secrets (for CI)
- **Notes:** No `.env.example` in repo yet; add before first deployment with placeholder values

**App-Level Config:**

- **`apps/api/src/config/env.ts`:** Zod schema defines required + optional env vars
  - Parses at startup; throws if required vars missing
  - Shared by all API modules via `ConfigModule`

- **Drizzle Config (`packages/db/drizzle.config.ts`):** Detects `DATABASE_URL_UNPOOLED` for migrations
  - If absent, falls back to `DATABASE_URL`
  - Neon-specific: pooled URL uses pgBouncer; unpooled is direct postgres
