## Avatar Sunset Ring Contract (D-07)

The Profil header avatar gets a circular Sunset gradient ring (design L1776: an absolutely-positioned `inset:-4px` circle behind a `border:3px solid var(--bg-app)`-ringed `AvatarTile`).

- Implementation mirrors `FestivalCard.tsx`'s existing `SunsetLayer` pattern (same `gradientSunset` token, same `react-native-svg` `LinearGradient`/`Defs`/`Stop` construction) but with a `Circle` primitive instead of a rounded `Rect`.
- Ring diameter = avatar size (88px, `AvatarTile`'s existing `AVATAR_SIZE`) + 8px (4px inset on each side, matching the design's `-4px` offset).
- A 3px `colors.bgApp` gap sits between the ring and the avatar itself (matches the design's `border:3px solid var(--bg-app)`) so the ring never touches the photo/initials edge-to-edge — this is what makes it read as a RING, not a background wash.
- Applies in BOTH color modes unchanged (Sunset is mode-invariant per CI §6/§3).
- **Documentation follow-up (not this agent's job, flagged for the plan):** D-07 also requires editing `docs/DEVELOPMENT_DECISIONS.md` (ADR-023) and `docs/brand/quiks-ci-v1.md` to widen the Sunset-usage rule from "mark and hero surfaces only" to "…and avatar/identity surfaces". That is a docs-authoring task for `gsd-plan-phase`/`gsd-executor`, not a UI-visual decision — this UI-SPEC only fixes what the ring looks like.

## Meta Line Contract (D-04, D-12)

Profil header renders, in order, on a single `bodySm`/`textMuted` line:

```
{identityLine}      ← D-12, OMITTED ENTIRELY if pronoun/age/gender are all empty
{displayName}        ← title1 (or title2 fallback), never translated
@{username}           ← countdown role, colors.primary, never translated
{metaLine}            ← "{n} Festivals · {n} Friends · seit {year} dabei"
```

- **Identity line** (`sie/ihr · 23 · weiblich` in the design): join only the NON-EMPTY optional fields with ` · `. Zero, one, two or three present values are all valid — the line is entirely absent (not rendered, no reserved height) when all three are empty, per the same "omit-if-empty" precedent `FestivalCard.tsx` already uses for the optional `place` field. Order is fixed: pronoun, age, gender.
- **Meta line**: `{n} Festivals · {n} Friends · seit {year} dabei`. `n Festivals` count sources the ALREADY-CACHED `festivalKeys.mine` query (`apps/mobile/lib/festival-queries.ts`) — no second network call (Claude's Discretion, resolved per `06-CONTEXT.md`'s own note). `n Friends` is the constant `0` this phase (FRND-02 not built) — still routed through a Lingui `plural` macro for correctness, not a bare string, since 0 is a real plural category. `{year}` is `Account.createdAt`'s year only (`new Date(createdAt).getFullYear()` — no full-date `Intl` formatting needed, a bare year has no locale-variant form). Recommend a pure, testable helper (`lib/profile-meta-line.ts`, mirroring `lib/date-range.ts`'s pattern) so this logic lands in the node-env Vitest runner rather than screen code.
- "Friends" is used as a literal, untranslated brand-voice word in BOTH DE and EN copy per the design source (the design's own German copy says "Friends", not "Freunde", consistently across the Friends tab, meta line and stat tile) — still routed through Lingui `t`/`plural` for I18N-01/lint compliance even though the DE and EN catalog values are expected to be identical.

**Open item for `gsd-plan-phase` (not resolved here — visual-only spec, this is a data-model decision):** whether `age` is stored raw or derived from a `birthDate` column is explicitly left open by `06-CONTEXT.md` D-12 ("Der Planner muss das explizit vorlegen, nicht still entscheiden"). This UI-SPEC only fixes the DISPLAY: age renders as a plain localized integer (e.g. `23`), however it is sourced.

## Theme Override Contract (D-08a)

Storage shape (mirrors `active-festival-storage.ts`'s MMKV idiom — own storage id, lazy `require`, error-swallowing):

- `ThemeOverride = 'system' | 'light' | 'dark'` — THREE stored states, satisfying the CONTEXT's "dritter Zustand" requirement even though the Mehr-screen `SettingsSwitch` UI only ever WRITES `'system'` (off) or `'dark'` (on) this phase; `'light'` exists in the type for forward-compatibility (a future "force light against a dark device" control) but has no writer yet.
- Effective mode: `override === 'dark' ? 'dark' : override === 'light' ? 'light' : resolveThemeMode(deviceScheme)` — the `'system'` branch is the UNCHANGED 05.1 `resolveThemeMode` call, so the hell-first invariant (only the exact device value `'dark'` yields night mode when following system) is preserved byte-for-byte.
- Default (no stored value / first launch): `'system'`.
- The `Switch` in Mehr → Darstellung reflects the CURRENT EFFECTIVE mode (checked = dark, whichever state produced it), not the raw override value — toggling it always writes an EXPLICIT `'dark'` or `'system'` (never `'light'`).

Visual: identical `SettingsSwitch` component as the dead notification switches, just `disabled={false}` and wired to this state instead of a no-op.

  the sanctioned fallback already recorded in § Typography (reuse `title2` unchanged — which also
  avoids the admin-stream collision-zone coordination for a single usage), or keep the 24/800

  derivation note, so `tokens.ts` stays self-explanatory. Do not land it as-is under the current
  name.
