<objective>
Move every component in `apps/mobile/components` onto the resolved-per-render theme, make the
floating navigation's glass genuinely mode-aware, build the Sunset gradient layer the Home hero
card does not have today, and tokenise the raw colour literals that would otherwise survive the
brand swap.

Purpose: the token swap in plan 03 changes values, but every consumer still freezes those values at
module import time — a mode change would not repaint anything. This plan is half of that migration
(components); plan 05 is the other half (screens). They touch disjoint files and run in parallel.
Output: eight re-themed components, one new gradient render path, zero raw colour literals.

Requirement-ID substitution (visible, recorded): no REQ-IDs exist for this phase; ADR-023 is the
traceability anchor for the CI work (see plan 05.1-01 objective for the full note).

**Correction to a RESEARCH claim, verified at plan time.** RESEARCH.md states there are zero
hardcoded hex values in `apps/mobile`. That is wrong: three raw rgba literals exist. One is in this
plan's scope (`AvatarTile`'s tint, mixed from the Limette that D-11 deletes — left alone it would
keep a green ring around every avatar after the brand swap); the other two are in plan 05's scope.
All three are replaced by the tokens plan 03 adds.
</objective>
