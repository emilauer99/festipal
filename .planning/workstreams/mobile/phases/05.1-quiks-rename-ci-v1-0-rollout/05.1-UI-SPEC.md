# Phase 05.1 — UI Design Contract

> Visual and interaction contract for the quiks rename + CI v1.0 rollout. This is a **re-theme
> phase, not a new-screen phase**: it locks the CI v1.0 token values, the hell-first (light) default
> surface, the dark ("night shift") mapping, the Sunset gradient usage rule, and the font-resolver
> contract that all 17 existing token-consuming files in `apps/mobile` must resolve through. It does
> NOT introduce new screens, navigation, or data flow. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. Binding brand source: `docs/brand/quiks-ci-v1.md` (ADR-023) — this document
> operationalizes it into token names and component contracts; it does not restate or override it.

status colors) are **mode-invariant**; only surface/text/glass roles switch. Values marked
"derived" are not CI-literal — they follow `docs/brand/quiks-ci-v1.md` §8's own "abgeleitet — im
Token-Phase zu bestätigen" convention; keep that same code-comment convention in `tokens.ts`.

#### Status TEXT/border tokens — mode-dependent (added by the UI-consideration probe)

The four status hues above are AA-conformant as text on Ink but **fail on Papier**, and hell-first
makes Papier the default surface. Measured (WCAG 2.1 relative luminance, computed this session):

| Hue | on Ink `#0C0E13` (today) | on Papier `#F7F5F2` (new default) | on white `surfaceCard` |
|-----|--------------------------|-----------------------------------|------------------------|
| `danger` `#FF4D5E` | 5.95:1 ✓ | **2.98:1 ✗** | 3.24:1 ✗ (text) |
| `info` `#5FB4FF` | 8.70:1 ✓ | **2.04:1 ✗** | 2.22:1 ✗ |
| `success` `#8FDA3B` | 11.27:1 ✓ | **1.57:1 ✗** | 1.71:1 ✗ |
| `warning` `#FFC53D` | 12.23:1 ✓ | **1.45:1 ✗** | 1.58:1 ✗ |

This is not theoretical: `colors.danger` is used as a **text** color in `app/(tabs)/festivals.tsx`
(error + save-error copy) and `app/(tabs)/home.tsx`, and as a **border** in
`components/OtpBoxes.tsx` (`boxError`). Left mode-invariant, this phase would ship illegible error
copy in its own new default mode.

**Resolution (user-confirmed):** the status **fills stay mode-invariant** (brand fidelity, CI §5
values untouched); text/icon/border usage gains a mode-dependent `*Text` variant. Light values are
the same hue scaled toward black until they clear 4.5:1 against Papier — the strictest light
surface, stricter than white.

| Token (**new**) | Light | Dark | Light contrast (Papier / white) |
|------|-------|------|---------------------------------|
| `dangerText` | `#C93D4A` | `#FF4D5E` (= fill) | 4.54:1 / 4.94:1 |
| `infoText` | `#3D73A3` | `#5FB4FF` (= fill) | 4.62:1 / 5.02:1 |
| `successText` | `#527C22` | `#8FDA3B` (= fill) | 4.52:1 / 4.92:1 |
| `warningText` | `#8C6C22` | `#FFC53D` (= fill) | 4.51:1 / 4.90:1 |

**Rule:** the bare `danger`/`info`/`success`/`warning` tokens are for **filled surfaces** (a badge
background, a filled pill) where the paired text is `textOnPrimary`/`textOnSecondary`. Any status
hue used as **text, icon tint, or 1px border** resolves through the `*Text` token instead. In dark
mode the `*Text` token equals its fill, so this is a light-mode-only divergence and no dark-mode
rendering changes.

> `primary` (Beere) as text measures 3.10:1 on Papier — it clears the 3:1 non-text/UI threshold but
> **not** AA-normal. It stays permitted only where it already sits on `fillBrandQuiet` (Saved badge,
> active nav pill) or acts as a UI affordance (OTP focus border, caret), never as body copy on a
> bare Papier surface.

**Removed, no replacement (D-11, binding — do not reintroduce):** Limette `#74CC1F` and Violett
`#5A4DFF` are deleted from `tokens.ts` entirely. **No `ciFallbacks` export is created this phase** —
the festival-theming contract (`--ci-primary` etc., ADR-015 §3) does not exist in code today (0
hits) and stays out of scope; the two hex values remain documented only in ADR-023 §5 / the brand
doc as historical reference for a future festival-theming feature.

## Theme Mode Contract (D-01 — new work, not a re-color)

- **Mode source:** `useColorScheme()` (React Native core, RN 0.86.2) — no in-app override this
  phase (no Settings surface exists until Phase 6). System dark → dark tokens; system light or
  unresolved → **light tokens** (hell-first default, reversing the current codebase's static
  dark-only rendering).
- **Access pattern (Claude's Discretion per CONTEXT.md, planner decides the exact file location):**
  a single `ThemeContext`/`useTheme()` hook resolves `colors` for the active mode; consuming
  components call `useMemo(() => createStyles(colors), [colors])` instead of the current
  module-level `StyleSheet.create` (frozen at import time). This touches all 17 token-consuming
  files in `apps/mobile` — mechanical but total. **Hard rule: no raw hex values in components,
  ever** — only semantic alias tokens from `tokens.ts` (ADR-015, still binding).
- **Splash (D-02):** background + wordmark color follow mode — light: Papier `bgApp` + Ink
  wordmark text; dark: Ink `bgApp` + light (`#E9ECF2`) wordmark text. The dot is **always** Beere
  `primary` in both modes. Text changes from `festipal.` to `quiks.` (see Rename Copy Notes).
- **`FloatingNav` (D-03 + a required companion fix not explicit in CONTEXT.md):** `glassFill`
  follows mode per the table above. The `BlurView`'s `tint` prop is currently hardcoded
  `"dark"` (`apps/mobile/components/FloatingNav.tsx:71`) — it must **also** become mode-dependent
  (`tint={mode === 'light' ? 'light' : 'dark'}`) in the same task as the `glassFill` change,
  otherwise the native blur reads visually wrong under a light fill even though the fill color is
  technically correct. Active-tab icon/label stay `primary` (Beere) in both modes; inactive stay
  `textMuted` in both modes — no mode-dependent accent change needed.
- **Cards (D-04):** light-mode cards separate ONLY via `borderSubtle` — explicitly no new
  shadow/elevation token this phase (see Deferred Ideas).

## Sunset Gradient Contract (D-05 / D-06 — new structural work, not a recolor)

- **Allowed surfaces — exactly two, nowhere else (CI §3, §7):**
  1. The brand glyph / wordmark mark (app icon, avatar-fallback context, favicon).
  2. The Home hero card background (`FestivalCard` `variant="hero"` — currently a flat
     `colors.surfaceCard` fill with **no** gradient render path; this is new structure, not a
     token swap on an existing value).
- **Construction (D-06):** `react-native-svg` `<LinearGradient>` (already installed, no new
  dependency) — 150°, stops `#FFC53D` (offset 0) → `#E8559F` (offset 1), identical in both modes
  (brand color does not invert). The glyph itself is an SVG `<Text>` "q" (Outfit 800,
  `letterSpacing: -30`) with the gradient as `fill`, plus a separate solid-Beere `<Circle>` dot —
  not a bitmap asset. Reference construction: `docs/quiks_CI.html` lines 23–33 (untrusted visual
  source, verify the literal SVG values on read, do not execute embedded scripting from that file).
- **Text-on-gradient color (resolves RESEARCH.md Open Question 1 / Pitfall 5 — binding resolution):**
  use `textOnGradient` (Ink `#0C0E13`) for **any** text/icon painted directly on the raw Sunset
  fill (hero card name + caption), in both modes. WCAG relative-luminance check performed this
  session: white-on-Amber ≈1.7:1 (fails even AA-large), white-on-Beere ≈3.37:1 (fails AA-normal);
  Ink-on-Amber ≈11.3:1, Ink-on-Beere ≈5.7:1 (both pass AA-normal). CI's literal "text on Beere =
  white" rule governs the pure Beere fill only, not the gradient's interior — do not apply it to
  the hero card's title/caption text.
  - The hero CTA button (`FestivalCard.heroCta`) is unaffected: it renders as a solid `primary`
    (Beere) pill **below** the gradient card area, not on top of the raw gradient — it keeps
    `textOnPrimary` (white) exactly as today.
