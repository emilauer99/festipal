sie tatsaechlich beweisen kann.

    - `foldForSort(value: string): string` — trimmt, senkt auf Kleinbuchstaben und faltet die
      Diakritika ueber eine explizite, im Modul definierte Zeichentabelle:
      `ä/à/á/â/ã/å -> a`, `ö/ò/ó/ô/õ -> o`, `ü/ù/ú/û -> u`, `é/è/ê/ë -> e`, `í/ì/î/ï -> i`,
      `ñ -> n`, `ç -> c`, `ß -> ss`. Bewusst KEIN `String.prototype.normalize` und keine
      Unicode-Property-Escapes: beide sind auf Hermes nicht garantiert, und genau diese Sorte
      stiller Annahme ist das Risiko, das D-12 benennt. Kommentiere das an der Tabelle.
    - `resolveCollator(): Intl.Collator | null` — Capability-Probe nach dem Vorbild von
      `intl-capability.ts`: prueft `typeof Intl` und `typeof Intl.Collator`, konstruiert in einem
      `try`/`catch` einen `new Intl.Collator(undefined, { sensitivity: 'base', numeric: true })`
      und verifiziert an einem festen Probepaar, dass `compare('ä', 'z') < 0` gilt. Schlaegt eines
      davon fehl, ist das Ergebnis `null` — eine Code-Point-Sortierung stellt `'ä'` (U+00E4) hinter
      `'z'` (U+007A) und ist damit an genau diesem Vergleich erkennbar. Das Ergebnis wird
      modul-lokal gecacht.
    - `createDisplayNameComparator(collator: Intl.Collator | null): (a: SortableFriend, b: SortableFriend) => number`
      — vergleicht primaer `displayName` (mit `collator.compare`, sonst ueber `foldForSort` und
      `<`/`>`), und loest Gleichstand IMMER ueber `username` auf. Der Tiebreak ist nicht kosmetisch:
      `username` ist eindeutig, also wird die Ordnung total und die Ausgabe unabhaengig davon, ob
      die Laufzeit-Sortierung stabil ist.
    - `sortFriendsByDisplayName<T extends SortableFriend>(friends: readonly T[]): T[]` — kopiert die
      Eingabe (`[...friends]`) und sortiert die Kopie; die Eingabe wird nie mutiert.
