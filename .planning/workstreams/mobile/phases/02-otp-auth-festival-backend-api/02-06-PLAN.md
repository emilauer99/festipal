<objective>
Close the single Phase 2 verification blocker (CR-01): `POST /api/v1/festivals/:festivalId/save`
crashes with an unhandled 500 for an authenticated visitor who has not yet completed their
profile (`GET /me` → `profile: null`, a documented reachable first-login state). The root cause
is that `my_festival.visitorId` is a NOT NULL FK into `visitor_profile.accountId`, and
`FestivalService.save()` never guards against a missing `visitor_profile` row — the insert throws
a Postgres `23503` FK violation that propagates as a raw 500.

Fix it as a three-layer vertical slice — contract, service, controller — plus the missing test:
1. Add a `409` profile-required response to `contract.saveFestival`.
2. Catch `23503` in `FestivalService.save()` and return `{ status: 'profile-required' }`.
3. Map that signal to the `409` in `festival.controller.ts`.
4. Add `save-profile-required.spec.ts` exercising the previously-uncovered path.

Purpose: make the gate-less save robust — it must return a clean, contract-documented error for
the reachable profile-null state instead of a 500, satisfying SEC-02's "save only writes
my_festival, never crashes" clause.
Output: hardened save endpoint + contract response + regression test.
</objective>
