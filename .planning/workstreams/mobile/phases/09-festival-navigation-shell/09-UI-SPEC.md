# Phase 9 — UI Design Contract

> Visual and interaction contract for the five-tab festival shell, the new app-wide `AppHeader`,
> the Dashboard tab (identity + Cashless WebView + crew counter), the two honest placeholder tabs
> (Timetable, Lageplan) plus the Aktivitäten placeholder, the festival Friends tab (FRND-07), and
> the `home` → `start` rename's copy impact. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker.
>
> **North-star sources:** `docs/concept/designs/quiks-v2/quiks-screens.template.html` (header
> markup L1364–1382; `05 Live` L1530–1587; `06b Crew` L1641–1668; `07 Timetable` L1670–1702;
> `08 Karte` L1704–1735) plus the header/nav bindings only present in the original bundle
> `docs/quiks_screen_designs.html` (`tbIcon`, `topHome`, `showWordmark`, `showTitleText`, `tb`,
> `navF`/`navG`). `09-CONTEXT.md` (D-01…D-21) is authoritative for scope and is user-locked; this
> document transcribes it into pixel/token/copy contracts and resolves every "Claude's Discretion"
> item the context left open for this agent. `docs/DEVELOPMENT_DECISIONS.md` §ADR-014 names the
> five tabs literally and drops the design's "Crew"/"Live" labels — **"Dashboard" and "Friends" are
> the binding UI labels, not the design's "Live"/"Crew".**
>
> Where a design element is explicitly excluded by a decision (Live-Act-Chip, header subtitle, the
> four dataless Dashboard blocks, SafeNow, Chats, presence/distance) it is not reproduced anywhere
> below — deliberate, not an omission. Every value is either an EXISTING token/component from
> `packages/ui/src/tokens.ts` / `apps/mobile/components/`, or is explicitly flagged **NEW** with its
> derivation shown. Do not invent parallel values.

## Spacing & Layout Scale

The project's real ported CI ramp (`spacingScale`/`layout`/`radiiScale` in `packages/ui/src/tokens.ts`) — **unchanged this phase**, same precedent as every prior phase. Do not round toward a generic 4/8/16/24/32/48/64 scale; this is the binding brand ramp.

| Token | Value | Usage this phase |
|-------|-------|-------------------|
| `spacingScale['sp-4']` | 8px | icon↔label gaps inside `StatTile`/placeholder icon-to-heading |
| `spacingScale['sp-5']` | 12px | `AppHeader` internal gaps (button↔title↔avatar) — the design's literal `gap:12px` (L1374) is an exact match, not a rounding; Dashboard's tile-row gap (design `gap:10px`, L1534, rounds to this token — same tolerance Phase 8 already applied) |
| `spacingScale['sp-6']` | 16px | `StatTile`/placeholder card padding; key-fact row gap (unchanged from existing `f/[festivalSlug].tsx`) |
| `spacingScale['sp-8']` | 24px | pill-button horizontal padding (unchanged app-wide) |
| `layout.screenPad` | 18px | screen horizontal padding — Dashboard, placeholder screens, Cashless WebView chrome, Festival Friends tab; also `AppHeader`'s internal left/right inset (the design's literal `14px`, L1374, is overridden toward this existing project-wide constant — same override precedent Phase 8 already applied to `retryButton`/`qrButton`) |
| `layout.topbar` | 56px | **newly adopted, not new** — this token already exists in `tokens.ts` and was unused until now. It is the `AppHeader` content-row height (below the safe-area top inset), the RN equivalent of the design's fixed `52px` header content row (L1364–1382) |
| `layout.hitMin` | 44px | minimum tap target — `AppHeader`'s home/back button (36px VISUAL circle, 44px tap target, same override precedent as Phase 8's `retryButton`), the avatar's own touch area, every `StatTile`/tile tap, every placeholder-screen control |
| `layout.scrollBottomPad` | 104px | Dashboard, Festival Friends tab, placeholder screens — every scrollable festival-tab screen clears the 5-tab `FloatingNav` the same way existing tab screens already clear the 4-tab one |
| `radiiScale['r-md']` | 16px | `StatTile`, placeholder icon container (if boxed), Cashless WebView chrome corners |
| `radiiScale['r-card']` | 22px | Festival Friends tab's reused `PersonRow` (unchanged from Phase 8), the festival 404/error state's retry button container styling (unchanged pattern) |
| `radiiScale['r-pill']` | 999px | `AppHeader` home/back button circle, primary buttons, Dashboard "Find friends" CTA |

Exceptions: none — `layout.topbar` is an existing token that simply had no consumer before this
phase.

## App Header Contract (D-02, D-03, D-04, D-06, D-08)

**The single biggest visual change this phase makes.** `AppHeader` is one component with three
states, replacing the native `Stack`/`Tabs` header everywhere in the authenticated app (four global
tabs, five festival tabs, four push screens).

### Structure (all three states)

An absolute, full-bleed overlay pinned to the top of the screen:

- `position: absolute; top: 0; left: 0; right: 0`, height = `insets.top + layout.topbar` (56px
  content row below the safe-area inset — the RN equivalent of the design's fixed 52px row,
  L1364–1382).
- Background: `colors.glassFill`, rendered via the same `BlurView` approach `FloatingNav` already
  uses (`BLUR_INTENSITY = 60`, `tint` follows the resolved mode) — reuse the pattern, do not
  reinvent a second blur constant.
- `border-bottom: 1px solid colors.borderSubtle` (design's literal border, L1365).
- Content row: horizontal padding `layout.screenPad` (18px, overriding the design's literal 14px —
  same project-wide override precedent as every prior phase), internal gaps `spacingScale['sp-5']`
  (12px, an exact match to the design's literal `gap:12px`), vertically centered within the 56px
  row, height `layout.topbar`.
- Every screen beneath the header must add top clearance equal to the header's own height
  (`insets.top + layout.topbar`) to its scrollable content — the same clearance idiom
  `layout.scrollBottomPad` already establishes for `FloatingNav` at the bottom. This touches every
  existing tab screen's content padding, not just the new ones.

### Left slot — home/back button

- 36px visual circle, `backgroundColor: colors.fillQuiet`, centered icon at size 18, stroke 2,
  color `colors.textPrimary`.
- Rendered inside a `layout.hitMin` (44px) minimum touch target — the design's literal 36px is a
  VISUAL size only, same override Phase 8 already applied to `retryButton`/`qrButton`.
- **Icon and action are state-dependent** (verbatim binding from the design bundle, not a
  paraphrase):
  - Pushed (any push screen): icon `ArrowLeft`. Action closes the push screen (`router.back()`
    equivalent). Accessibility label "Back".
  - Festival context, not pushed: icon `Home`. Action = `leaveFestival(router)` (existing function,
    D-02 — its `/home` literal target updates to `/start`, D-19). Accessibility label
    "Leave festival".
  - Global context, not pushed: icon `Home`. Action navigates to the Start tab. Accessibility
    label "Go to Start". **On the Start tab itself this is a visible, functional, but
    NO-OP action (D-06)** — tapping it re-targets the tab it is already on. This is deliberate:
    a control that moves position or disappears is harder to learn than one that occasionally does
    nothing. Not a `SoonToast` case — nothing is missing, the destination is already reached.

### Center slot — wordmark / title

- Global context, not pushed: "quiks." wordmark text at the new `headerWordmark` role (21px, see
  § Typography), dot in `colors.primary`, identical text-composition pattern to `SplashView`'s
  wordmark (text run + colored dot span), just smaller. **Shown uniformly across all four global
  tabs — no per-tab title.**
- Festival context, not pushed: festival name at the new `headerTitle` role (17px), `numberOfLines`
  1, tail-ellipsize (same long-text guard app-wide). On the festival 404/error state (D-10), falls
  back to a generic localized title (DE "Festival" / EN "Festival") since no real name is available.
- Pushed (any push screen): the screen's own title at `headerTitle` (17px), `numberOfLines` 1,
  tail-ellipsize — "Profile", "Friends", "Cashless", "QR Code" per the pushed screen.
- Live-act chip (design's `artistChipShow`) is explicitly NOT built this phase (deferred — needs
  Timetable data).

### Right slot — avatar

- 32px `AvatarTile` (see § Avatar Size Contract), sourced from the already-shared `['me']` query
  (D-04) — no new fetch.
- **No `AvatarSunsetRing`.** The design's own header markup (L1380) renders the avatar bare, with
  no ring — the ring stays reserved for the Profil screen's 88px header avatar and the (Phase 8)
  friend-detail card's 88px avatar, the app's two dedicated "identity moment" surfaces. A third,
  smaller ring on every screen's header would read as gradient noise on constant repeat, against
  CI §3's "maximal zwei Flächentöne pro Screen" spirit.
- Tap always pushes `app/profil.tsx`, on every state including when already on Profil (the design's
  binding is unconditional, L1380 carries no `sc-if`) — a harmless duplicate push, not a broken
  state. Recorded as a resolved edge case, see § UI Considerations row 4.
- Existing Mehr → Konto → Profil entry point stays exactly as-is (D-04: two entries, one
  destination, no second code path).

## Dashboard Contract (D-07, D-08, D-09, D-10, D-11)

### Identity block (unchanged, minus the name)

The two key-fact rows (`CalendarClock`/`MapPin` icons at `colors.primary`, `bodySm` text) carry over
verbatim from the existing `f/[festivalSlug].tsx` `keyFacts`/`keyFactRow` styles. The `name` heading
above them is REMOVED — the festival name now lives exactly once, in `AppHeader` (D-08).

### Stat tile row — `StatTile` **NEW component**

A row of 1–2 tiles, `flexDirection: row`, `gap: spacingScale['sp-5']` (12px), each tile `flex: 1`.

```
StatTile props: { icon: LucideIcon, label: string, value?: string, tone?: 'brand' | 'default' }
```

- Background `colors.surfaceCard`, border `colors.borderSubtle` 1px, radius `radiiScale['r-md']`
  (16px), padding `spacingScale['sp-6']` (16px) — matches `festipal-ds.js`'s `StatTile` structure
  (icon+eyebrow row, then a value row) ported to RN.
- Eyebrow row: icon at 15px in the tone's accent color (`colors.primary` for `tone="brand"`,
  `colors.textSecondary` for `tone="default"`) + `micro`-role uppercase label.
- Value row: `title2`-role value text (see § Typography deviation note) + optional `bodySm`
  trailing unit/word.

**Cashless tile** (`tone="brand"`, icon `Wallet`, label "Cashless"): rendered ONLY when
`festival.cashlessUrl` is non-null — a hard omission, never a dampened/inert placeholder (ADR-011,
D-09). No `value` is ever rendered (the real balance lives behind the embedded page, not in this
app's own data — showing a number here would be fabricated data, the same rule Phase 6's Profil
screen already applies to its own outlook blocks). In place of a value, render a trailing
`ArrowRight` (14px, `colors.textMuted`) so the tile still communicates "tap to open" without
implying a measurement. Tap pushes `app/cashless.tsx`.

**Crew tile** (`tone="default"`, icon `Users`, label "Freunde hier"/"Friends here", **always
rendered — D-11**): two distinct value-row renderings depending on the friend count from the same
`GET /festivals/:festivalId/friends` response the Festival Friends tab reads (D-18, one query, one
cache entry, one invalidation):

- Count > 0: `title2`-role numeral + `bodySm` "Freunde hier"/"Friends here" trailing word (the
  StatTile happy path).
- Count === 0: the value row is REPLACED by the precondition sentence (§ Copywriting Contract) at
  `bodySm`, `colors.textMuted` — never a bare "0". This is D-11's rule made concrete: a zero is a
  statement ("nobody yet"), not an empty state, so it gets a sentence, not a blank numeral.

Tap switches the active tab to Friends within the festival navigator (matches the design's `goCrew`
binding).

When `cashlessUrl` is null, the row renders the Crew tile alone — `flex: 1` on a single child
already fills the row width with no special-case styling needed.

### Cashless WebView screen (`app/cashless.tsx`, D-09)

Full-bleed `react-native-webview` `WebView` below `AppHeader`'s push state (title "Cashless").
- Source: `{ uri: festival.cashlessUrl }`, validated `https://`-only before the screen is even
  reachable (the Dashboard tile itself is omitted otherwise, D-09) — no in-screen protocol check
  needed as a SECOND gate, but `originWhitelist` restricted to the URL's own host is still the
  WebView's own sandboxing per ADR-011.
- Loading: centered "Lädt Cashless…"/"Loading Cashless…" text (existing `helper` style pattern),
  shown between `onLoadStart` and `onLoadEnd`.
- Error (`onError`/`onHttpError`): existing error pattern (`dangerText` text + pill Retry button
  that reloads the `WebView` via a ref — the screen itself is not left).
- **Explicitly excluded from this screen** (ADR-011, D-09): no native balance element, no booking
  list, no pay QR, no host-URL chrome mock (the design's `09 Cashless` browser-chrome illustration,
  L1737–1758, is a mockup of the DESTINATION page's own content, not something this app builds —
  the app only supplies the WebView frame).

### Festival not-found / unreachable (D-10)

Moves from the screen level to the FESTIVAL NAVIGATOR layout level: one `getFestival(slug)` query
gates the entire festival area (all five tabs, not just Dashboard). On 404 or a transport error, the
whole area is replaced — no tab bar, no tab content, only the message plus `AppHeader`'s home/back
button as the way out. Visual treatment is the EXISTING `f/[festivalSlug].tsx` centered
heading/helper/retry pattern, unchanged in copy and style, just relocated one layer up. The
`clearActiveFestivalSlug()` 404 effect moves with it.

**One new shared component**, used by all three tabs (Aktivitäten, Timetable, Lageplan) — never
