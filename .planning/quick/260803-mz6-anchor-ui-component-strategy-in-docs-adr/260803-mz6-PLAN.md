<objective>
Anchor the UI component strategy decided by the user (2026-08-03) in the project's
canonical docs. This is a DOCS-ONLY change: no phase artifacts, no code, no packages.

The decision (supersedes an earlier idea of adopting a third-party RN UI framework):
- **Mobile app** (`apps/mobile`, Expo/RN): NO third-party UI component framework/library.
  Custom components built on RN primitives (`View`, `Text`, `TextInput`, `Pressable`, …),
  living in `packages/ui`, styled exclusively via shared design tokens
  (`packages/ui/src/tokens.ts`). No ad-hoc `StyleSheet` values scattered in screens —
  styling flows through tokens/shared primitives.
- **Admin web** (`apps/admin`, Next.js 15): shadcn/ui + Tailwind (confirms ADR-003),
  with the explicit rule that hand-written CSS is minimized — Tailwind utilities +
  shadcn components only; custom CSS requires justification.
- Rationale to capture: minimize custom CSS/styling code, consistency, avoid
  third-party UI-kit lock-in and churn on RN, easier design fidelity to Claude Design
  (Phases 4–6) with owned components.

Purpose: give future planning/execution a single authoritative decision to cite instead
of re-litigating UI framework choices per phase.
Output: an appended ADR in docs/DEVELOPMENT_DECISIONS.md + aligned root CLAUDE.md.
